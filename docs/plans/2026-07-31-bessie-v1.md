# Bessie V1 implementation plan

**Date:** 2026-07-31
**Status:** Approved for implementation by Jordan's request to build a Mac-testable V1
**Repository:** `/home/hermes/code/bessie` (Mac mirror: `/Users/jordanstella/GitHub/bessie`)

## Outcome

Build a native macOS Bessie V1 alpha that completes the core local Herdr loop:

> Discover/connect to Herdr → choose a workspace → understand and shape tabs/panes → work in real libghostty terminals → see attention → quit without disrupting Herdr → reconnect accurately.

The first handoff is **Mac-testable**, not a claim that every release acceptance criterion is production-hardened. Any criterion not exercised must be named in the final test report rather than papered over.

## Review findings and decisions

The retained Bessie work already contains enough product and protocol definition to start. The key evidence is:

- Herdr `0.7.5` / protocol `17` exposes the required public JSON state/control methods.
- The terminal-session bridge has already driven two live Herdr panes into independent AppKit/Metal libghostty surfaces locally and over SSH.
- The focused V1 scope, workspace behavior, terminal boundary, capability map, and visual system are specified.
- The Mac has Xcode 26.6 and Swift 6.3.3 but no Herdr or supported agent CLI installed.

Implementation choices resolved for this run:

1. **Create the repository now.** Jordan's request is the previously required approval.
2. **Use a pure-Swift BessieCore first.** A narrow adapter around public Herdr surfaces is the shortest path to a native vertical slice. Preserve protocol boundaries so a shared Rust core can replace transport internals later without rewriting UI.
3. **Require or select a compatible Herdr runtime; use an isolated local build for development verification.** The product must not silently overwrite a system runtime. The test build may compile the pinned Herdr source into `.local/` and use a repository-local config.
4. **Use public JSON and terminal bridges only.** No private bincode protocol and no Bessie daemon.
5. **Treat events as invalidation hints.** Subscribe, buffer during bootstrap, resnapshot after events, and retain bounded polling only as a recovery fallback.
6. **Use the composite terminal input path.** Raw committed text from libghostty; intercepted mode-aware special keys and paste through Herdr JSON methods; resize and scrolling through the terminal controller.

## Milestone 1 — Native shell and reproducible build

Create a Swift Package Manager app with:

- `BessieApp` executable target;
- `BessieCore` library target;
- `BessieCoreTests` and focused app-model tests;
- exact `libghostty-spm` `1.3.2` dependency;
- native resources copied/adapted from the Bessie design system;
- packaging script that produces `dist/Bessie.app` with a valid Info.plist;
- VPS→Mac sync and verification scripts.

**Exit:** `swift test`, release build, and app packaging pass on the Mac; the app opens to a real Connect state.

## Milestone 2 — Herdr discovery, compatibility, snapshot, and recovery

Implement:

- runtime locator with explicit path override, normal PATH candidates, and development-local candidate;
- version/protocol/capability diagnostics;
- public Unix-socket NDJSON request transport;
- request ID correlation and typed errors;
- acknowledged event subscription plus snapshot bootstrap;
- event-buffer/resnapshot convergence and reconnect backoff;
- app presentation persistence limited to last workspace and preferences.

Support honest states: not found, stopped, incompatible, connecting, connected, retrying, and lost.

**Exit:** a live Herdr session appears from `session.snapshot`; equivalent Herdr-side mutations appear without restarting Bessie; disconnect/restart reconverges.

## Milestone 3 — Workspaces, tabs, panes, and layout projection

Model only Herdr-owned facts and project the public snapshot into native views. Implement actions for:

- workspace create, focus/open, rename, reorder, close;
- tab create, focus, rename, reorder, close;
- pane split, focus, resize, swap, move, zoom, rename, close;
- recursive split layout rendering and selected/focused state;
- destructive confirmations and focus fallback rules from the interaction spec.

Use direct socket methods where CLI wrappers are incomplete (notably reorder and exact split ratios). Every action must converge from the subsequent Herdr snapshot rather than mutating a durable local copy.

**Exit:** representative Bessie mutations are visible immediately in a live Herdr snapshot/TUI, and Herdr-side mutations converge back into Bessie.

## Milestone 4 — Real libghostty pane controller

For every visible pane:

- create one `GhosttyTerminal` AppKit/Metal surface with `InMemoryTerminalSession`;
- launch `herdr terminal session control <pane>` with the current grid;
- decode NDJSON `terminal.frame` envelopes and feed bytes in sequence;
- detect gaps, interruption, process exit, and controller conflicts;
- debounce/route grid resize;
- preserve one controller per pane across SwiftUI redraws;
- reconnect for a full frame after stream failure;
- release controllers when panes leave the visible layout without closing Herdr panes.

Composite input:

- ordinary committed/IME text through libghostty's raw write callback;
- intercept supported special keys and send semantic key names through `pane.send_keys`;
- intercept paste and send text through `pane.send_input.text` so Herdr applies live bracketed-paste mode;
- intercept wheel/page scrolling and send `terminal.scroll` commands to Herdr.

Unsupported mouse/focus-reporting and Kitty graphics must be explicitly described as unavailable.

**Exit:** two panes render distinct live shells, accept Unicode and special-key input, paste, resize, scroll, survive app quit/reopen, and remain usable from Herdr.

## Milestone 5 — Product surfaces and native visual identity

Implement the four focused V1 surfaces:

1. **Connect** — discovery, compatibility, setup, start/retry.
2. **Workspaces** — chooser/switcher with tab/pane counts and rolled-up attention.
3. **Workspace** — tab strip, recursive terminal grid, pane chrome, layout actions, new pane/start process.
4. **Attention** — Herdr-reported blocked/done items whose universal action is **Open pane**.

Add a reduced native Settings window for appearance, cow-print intensity/motion, terminal font size, pane gap, notifications, startup behavior, and diagnostics.

Adapt the approved warm off-white / black / red visual system and cow-print assets natively. Keep motion restrained and obey Reduce Motion. Do not import deferred dashboard/IDE screens.

**Exit:** the app is coherent and recognizably Bessie, not generic SwiftUI chrome; keyboard/focus behavior is usable; empty/error states are intentional.

## Milestone 6 — Process launch and attention

Implement:

- new shell pane via Herdr split/tab/workspace primitives;
- supported-agent launch from Herdr's manifest/capability data where available;
- disabled/reason state when the chosen agent binary is absent;
- semantic agent labels and `blocked`, `working`, `done`, `idle`, `unknown` display;
- open-pane attention navigation without inferred approval buttons.

The Mac currently has no supported agent CLI, so automated/live verification may use model fixtures for the UI and must report the missing live-agent prerequisite honestly.

**Exit:** shell launch works live; agent launch request construction and UI state are tested; a real agent check runs only if an installed supported agent is available.

## Milestone 7 — Verification and Mac handoff

Automate and execute:

- unit tests for decoding, transport framing, compatibility, projection, layout, and terminal sequence handling;
- integration tests using a fake public API/terminal process where deterministic behavior helps;
- live isolated Herdr smoke: connect, snapshot, create/rename/reorder/focus/close workspaces and tabs; split/resize/swap/move/zoom/rename/close panes; two terminal streams; input/output/resize; detach/reconnect;
- release packaging and launch;
- screenshot capture and visual inspection;
- process-survival check after quitting Bessie.

Produce:

- `/Users/jordanstella/GitHub/bessie/dist/Bessie.app`;
- `README.md` with one-path test instructions;
- `docs/reports/mac-v1-alpha.md` with exact commands/results, exercised criteria, known gaps, and reset/cleanup instructions.

## Validation commands

Ordinary checks from the VPS repository:

```bash
./scripts/check.sh
./scripts/mac-verify.sh
```

The Mac verifier must run real commands and fail on failed tests/build/smoke checks. A screenshot or successful compilation alone is insufficient.

## Mac-testable stop condition

Stop the autonomous implementation loop only when all of these are true, or a genuinely external prerequisite blocks further progress and is documented:

1. `./scripts/check.sh` passes.
2. `./scripts/mac-verify.sh` passes all available automated and live checks.
3. `dist/Bessie.app` exists on the Mac and launches without crashing.
4. A live isolated Herdr session is visible in Bessie.
5. At least two real libghostty panes display distinct Herdr terminals and pass observable input/output plus resize checks.
6. Representative workspace, tab, and pane mutations work in both directions.
7. Quitting/reopening Bessie preserves the Herdr processes and reconnects.
8. The user can begin testing from the README without installing global software or guessing paths.
9. The report distinguishes exercised behavior from known limitations; no acceptance criterion is falsely marked complete.

## Explicit non-goals for this run

- remote Herdr sessions;
- multiple runtime endpoints;
- graphical approval inference;
- generic editor/browser/file/worktree/plugin surfaces;
- private Herdr protocol reuse;
- Rust FFI absent evidence that Swift public adapters cannot satisfy the vertical slice;
- App Store signing/notarization;
- publishing or pushing the repository.
