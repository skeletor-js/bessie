# Shepherd — draft implementation plan

**Date:** 2026-08-02
**Status:** Draft / Proposed — **not approved for implementation**
**Product source:** [`../roadmap/shepherd.md`](../roadmap/shepherd.md)
**Horizon:** Post-V1

Do not start coding from this document until Jordan marks it **Approved** and M0 is complete. If this draft and the roadmap conflict, **the roadmap wins** until this file is re-approved.

## Goal

Ship **Shepherd**: a Bessie-owned, **invoke-only** corner chat that uses a **BYOK model (OpenAI or xAI)** to interpret intent and **immediately dispatches** work to a **new** real Herdr agent (user **default kind** + **default spawn location**), then gets out of the way.

**Out of v1:** status-on-ask, existing-agent targeting, other model providers, alerts.

## Non-goals (v1)

- Persistent Shepherd sessions
- Attention / alerts
- Status / “what’s going on?”
- Target or reuse existing agent panes
- Coding labor in the corner
- Confirm dialog before start
- Use-case multi-agent routing (later)
- Existing-agent targeting and broadcast (later Shepherd milestone; not a standalone product)
- Anthropic/other providers beyond OpenAI and xAI

## Architecture (proposed)

```text
ShepherdPanel (SwiftUI)
  → ShepherdSession (ephemeral UI state)
  → ShepherdIntentClient (OpenAI | xAI BYOK → schema: dispatch | refuse | clarify)
  → ShepherdDispatcher (kind + placement + HerdrProcessLauncher + first prompt)
  → existing HerdrSocketAPI / snapshot / focus pane
```

- **BessieCore (pure):** intent schema, kind resolution, placement mapping, dispatch planner tests
- **BessieApp:** panel, settings (default agent, spawn location, provider + Keychain), Open pane
- Reuse `AgentCatalog`, `HerdrProcessLauncher`, `AgentSemanticName`, process-launch busy retry

## Preferences

| Key | Meaning |
| --- | --- |
| Default agent kind | Catalog `kind` string |
| Default spawn location | Enum → `NewProcessPlacement` / split-or-tab |
| BYOK provider | `openai` \| `xai` |
| BYOK secret | API key in Keychain |

## Intent schema (v1)

```text
dispatch { brief, kind? }   // always implies new agent
refuse { reason, offer_dispatch? }
clarify { question }
```

No `status`. No `target: existing`. Existing-target user text → refuse/clarify (“not in Shepherd yet”) or offer a **new** dispatch (M0/M4 picks the exact copy).

## First prompt

After successful `agent.start`, deliver brief only when readiness contract from M0 allows (`pane.send_input` / keys). Never claim agent acceptance from timeout alone.

## Milestones

Match roadmap: M0 spike → M1 prefs → M2 panel+BYOK → M3 dispatch (new only) → M4 NL kind override + refuse → M5 harden → M6 status later → M7 existing-agent targeting, routing, and reviewed broadcast later.
